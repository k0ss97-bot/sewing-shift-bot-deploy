# WMS — актуальный handoff

Дата обновления: 2026-07-27. Рабочая ветка: `codex/wms-integration`.

## Что интегрировано

- WMS перенесена поверх актуального `main` (`5eb1263`).
- `miniapp_server.py` обслуживает `/api/wms/*` и проверяет сессию, CSRF и роль.
- Доступ имеют активный администратор и активный сотрудник с должностью `Кладовщик`.
- `employee_id` берётся только из аутентифицированной серверной сессии.
- Добавлены мобильные экраны: приёмка, размещение, перемещение, инвентаризация и списание.
- Администратор может создать ячейку и привязать товарный штрихкод из ТСД.
- Товарный штрихкод разрешается через `/api/wms/barcode/resolve`.
- Каждая мобильная операция передаёт уникальный `request_key`.

## Исправления складского ядра

- Остаток хранится отдельно для каждой ячейки: уникальный ключ включает `location_id`.
- Частичное размещение и перемещение больше не переносят весь остаток одной строкой.
- Добавлены ограничения `quantity >= 0` и `0 <= reserved_quantity <= quantity`.
- Postgres-соединения изолированы по потокам `ThreadingHTTPServer`.
- Репозиторий получает строки `DictCursor`, доступные и по индексу, и по имени поля.
- Исправлен вызов `repo.get_stock_rows()` в API.
- Исправлен SQLite cursor в bridge и конфликт по `legacy_sqlite_id`.
- Инвентаризация идемпотентна по `wms_inventory_counts.request_key`.
- Добавлена миграция `003_stock_per_location.sql` для уже созданной схемы.
- Seed создаёт системную ячейку приёмки `RECEIVE-01`.

## Что необходимо перед production-запуском

1. Поднять PostgreSQL 15+ и создать отдельную БД WMS.
2. Установить production-зависимости из `requirements.txt`.
3. Задать `WMS_DATABASE_URL` только в серверном окружении.
4. Выполнить `python -m wms.migrate`.
5. Создать реальные ячейки склада в интерфейсе администратора.
6. Выполнить первоначальный bridge на резервной копии и сверить суммы.
7. Прогнать `tests/test_wms.py` с доступной тестовой Postgres — локально эти тесты пропускаются без БД.
8. Только после сверки включать ТСД сотрудникам.

## Важная граница гибридной архитектуры

SQLite по-прежнему обслуживает производственные маршруты, а Postgres — адресное
хранение WMS. Bridge нельзя считать полноценной двусторонней транзакцией.
До окончательного перевода складских записей на один источник данных необходимо
контролировать сверку общих остатков и журналировать расхождения. Периодический
bridge не должен без проверки перезаписывать результаты операций ТСД.
