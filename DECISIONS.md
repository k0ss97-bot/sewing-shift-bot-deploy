# DECISIONS

## D-001 — Два хранилища и outbox

Производство остаётся в SQLite, адресный WMS и marketplace read models — в PostgreSQL. Подтверждённая упаковка создаёт durable SQLite outbox. Повторная доставка идемпотентна по `request_key`.

## D-002 — Готовый выпуск только после WMS-приёмки

План, раскрой и незавершённая упаковка не считаются готовым складским выпуском. Аналитический факт берётся из `production_receipt` в зоне `RECEIVE`.

## D-003 — Маркетплейсы read-only

Приложение читает каталог, цены, остатки, заказы, поставки, возвраты, финансы и аналитику. Оно не изменяет карточки, цены, marketplace-остатки и заказы.

## D-004 — Учебный режим не уничтожает строгие маршруты

Администратор выбирает режим для новых партий. Значение хранится в SQLite, изменение журналируется с сотрудником и временем. Существующие партии сохраняют snapshot своего режима.

## D-005 — Reconciliation не ремонтирует данные автоматически

Сверка SQLite → PostgreSQL работает read-only в отношении WMS, записывает диагностический результат в SQLite и поднимает уведомление. Исправление расхождений выполняется только отдельной контролируемой процедурой.

## D-006 — Unit-тесты не наследуют production DB URL

Runner принудительно подменяет WMS URL на тестовый. Для реальных PostgreSQL-тестов используется только `TEST_WMS_DATABASE_URL` с явным test-именем базы.

## D-007 — Test discovery по всем каталогам

Тесты из корня и namespace-каталога `tests/` загружаются явно и дедуплицируются по unittest ID. Итог всегда публикует discovered/executed/passed/failed/skipped/excluded.

## D-008 — Код, тест, релиз и живая приёмка — разные статусы

Наличие функции в коде, зелёный test, активный release и подтверждённая бизнес-операция учитываются отдельно. `/health` не заменяет E2E.
