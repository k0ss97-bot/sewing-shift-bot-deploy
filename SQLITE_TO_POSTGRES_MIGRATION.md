# Перенос оперативных данных SQLite → PostgreSQL

Переключение выполняется только поэтапно. Наличие таблиц PostgreSQL само по себе не разрешает менять основной источник записи.

## Последовательность

1. **Inventory.** Зафиксировать release manifest, перечень таблиц, владельца данных и допустимое окно остановки. Проверить восстановление обеих баз из резервной копии.
2. **Shadow copy.** Копировать строки пакетами с идемпотентным ключом, не меняя production read/write path. Для каждой таблицы хранить row count и детерминированную контрольную сумму без персональных данных в логах.
3. **Dual read.** Основной ответ остаётся SQLite; PostgreSQL читается в фоне. Расхождения записываются в `migration_control.table_checkpoints` и метрики, но не скрываются fallback-значением.
4. **Canary.** После остановки записи в переносимую таблицу повторить финальный delta-copy. Требуются совпадение count/checksum, lag ≤ 5 секунд, проверенный rollback, мониторинг и явное одобрение оператора.
5. **Cutover.** Переключать по одному вертикальному модулю, начиная с master data. Каждое изменение источника записи фиксировать в `migration_control.cutover_events` с предыдущим состоянием.
6. **Verification.** Проверить создание, изменение, идемпотентный повтор, отчёты и сверку остатков. SQLite остаётся read-only rollback-копией на согласованный период.
7. **Complete.** Выводить старый путь из эксплуатации только после полного backup/restore drill уже с PostgreSQL.

## Немедленный rollback

- остановить новые записи;
- вернуть предыдущий write flag из последнего `cutover_events.previous_state`;
- применить обратный delta только после отдельной сверки и одобрения;
- не удалять PostgreSQL-строки и не «лечить» расхождения ручным UPDATE без audit event;
- оформить incident и повторно пройти все gates.

## Запрещено

- включать несколько web workers, пока хоть один основной writer остаётся в SQLite;
- считать совпавший row count достаточным без checksum;
- продолжать cutover при неизвестном lag, отсутствующем restore drill или непроверенном rollback;
- делать неидемпотентный dual write.
