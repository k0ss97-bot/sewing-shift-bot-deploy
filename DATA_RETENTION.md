# Политика хранения данных

Дата утверждения в коде: 2026-08-09. Владелец политики: администратор сервиса.

## Классы данных

| Данные | Назначение | Срок | Действие после срока |
|---|---|---:|---|
| Фото производственного брака | доказательство качества и разбор причины | 365 дней | удалить бинарный файл; оставить факт брака, причину, количество и контрольную запись |
| Security events | расследование входов и административных действий | 180 дней | автоматическое удаление старых событий |
| Rate-limit buckets | защита входа | 24 часа | автоматическое удаление |
| Web-сессии | авторизация | до 12 часов, idle 45 минут | отозвать/удалить |
| Смены, движения, партии, задания, дефекты | производственная и складская прослеживаемость | 7 лет | архивировать; удаление только по утверждённому акту |
| ФИО и Telegram ID сотрудника | идентификация исполнителя | срок работы + утверждённый кадровый срок | псевдонимизация только по утверждённому акту; история операций не удаляется |

## Реализация

- Новые фото не записываются base64-строкой в SQLite. Они сохраняются в `DB_DIR/private-blobs` как content-addressed файлы с правами `0600`; в БД остаются ключ, SHA-256 и размер.
- EXIF и другие метаданные удаляются при загрузке, изображение проверяется и ограничивается 20 мегапикселями/2 МБ.
- `scripts/apply_data_retention.py` сначала переносит старые base64-фото, затем показывает dry-run. Удаление выполняется только с `--apply`.
- `sewing-data-retention.timer` применяет правило еженедельно. Резервные копии истекают по собственному сроку, поэтому удалённый файл может сохраняться в backup до окончания retention backup.

## Эксплуатационные ограничения

Каталог защищён правами ОС, но шифрование диска и off-site object storage настраиваются инфраструктурой. До включения шифрования тома статус encryption-at-rest нельзя считать подтверждённым. Монитор создаёт критическое событие без `DATA_AT_REST_ENCRYPTION_*`, а off-site репликация вообще не запускается без свежего (не старше 90 дней) файла `.encryption-at-rest.json` на отдельном mount. Ключи и секреты запрещено хранить в Git, отчётах и release manifest.
